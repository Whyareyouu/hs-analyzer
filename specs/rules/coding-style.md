# Кодстайл

## Общие правила

- Язык кода: Go `1.21+`.
- Язык комментариев и commit message: русский.
- Изменения должны быть минимальными и локальными, без лишних рефакторингов.
- Нельзя смешивать инфраструктурную, доменную и форматирующую логику в одном месте.

## Стиль Go-кода

- Предпочтение коротким, прямым функциям без лишней абстракции.
- Ошибки оборачиваются через `fmt.Errorf(...: %w)`, если важен контекст.
- `nil`-проверки делаются явно.
- Имена структур и методов должны оставаться предметными: `PowerParser`, `DeckParser`, `Pipeline`, `Analyze`, `Format`.
- Если есть существующий конструктор вида `NewX`, продолжать тот же паттерн.

## Изменения файлов

- Для ручных изменений использовать patch-подход.
- После правок обязательно запускать `gofmt`.
- Не делать массовые переименования без необходимости.
- Не трогать чужие или несвязанные изменения.

## JSON и formatter

- JSON должен быть человекочитаемым, а не только техническим.
- Если в событии есть карта, по возможности добавлять `name` и `info` из `data/cards.json`.
- Если в событии есть только `entity_id`, нужно пытаться обогатить его через `state.State` или данные parser.
- Для JSON использовать стабильные имена полей в `snake_case`.

## Работа с текстом карт

- Текст из `cards.json` должен очищаться от HTML и служебных меток вроде `[x]`.
- Не экранировать HTML в JSON там, где ожидается человекочитаемый текст.
