# Тестирование

## Главное правило

Для parser-тестов использовать только реальные данные из каталога `logs/`.

## Что запрещено

- Нельзя выдумывать лог-строки для parser-тестов, если нужный кейс уже есть в `logs/`.
- Нельзя подменять реальные фрагменты синтетическими аналогами “похожего формата”.

## Что нужно делать

- Для `PowerParser` брать фрагменты из `logs/Power.log`.
- Для `DeckParser` брать данные из `logs/Decks.log`.
- Для `LoadingScreenParser` брать данные из `logs/LoadingScreen.log`.
- Для helper-логики использовать test helper, который вырезает реальные строки по подстроке.

## Какие тесты обязательны

- unit-тест на новый parser-кейс
- formatter-тест на новый тип вывода
- если меняется CLI-поведение, добавить/обновить тесты в `cmd/hsanalyzer/root_test.go`

## Команды проверки

Минимум перед завершением задачи:

```bash
gofmt -w <измененные файлы>
go test ./...
```

Если проблема упирается в sandbox build cache, допускается запуск `go test` с повышенными правами.
