# Правила Проекта

Этот каталог фиксирует рабочие правила проекта для любой внешней нейросети или coding-agent.

Цель:
- не ломать сложившийся кодстайл
- не выдумывать данные там, где уже есть реальные логи
- сохранять совместимость с текущей архитектурой `parser -> analyzer -> pipeline -> formatter -> CLI`

Содержимое:
- [architecture.md](./architecture.md) — обязательные архитектурные ограничения
- [coding-style.md](./coding-style.md) — стиль кода и соглашения по изменениям
- [testing.md](./testing.md) — правила тестирования и использования реальных логов
- [cli-output.md](./cli-output.md) — правила для CLI и выходных файлов
