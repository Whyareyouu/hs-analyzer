# Skill: Parser Workflow

## Базовый подход

- Новый parser-кейс всегда строится от реального лога из `logs/`.
- Сначала найти точную строку или окно строк.
- Потом добавить/изменить regex и parser-логику.
- Затем зафиксировать это тестом именно на этом реальном фрагменте.

## Приоритеты

- Сначала корректный `game.Event`.
- Потом достаточные данные для formatter.
- Если formatter не сможет восстановить имя сущности из состояния, parser должен протащить `card_id` и `name` в событие.

## Для Power.log

- Особое внимание на:
  - `BLOCK_START`
  - `TAG_CHANGE`
  - `EntityChoices`
  - `SendChoices`
- Дубли `PowerTaskList` нужно фильтровать осознанно, а не глобально.

## Когда добавлять новые поля в event

Добавляй их, если:
- итоговое состояние теряет часть информации к моменту форматирования
- в JSON нужен человекочитаемый output
- данные уже присутствуют в реальном логе в момент парсинга
